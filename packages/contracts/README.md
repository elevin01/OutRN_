# @outrn/contracts — the v1 API contract

The agreement between the OutRN UI and backend: [zod](https://zod.dev) schemas (runtime
validation), the TypeScript types inferred from them, error codes, and fixtures. Depends on zod
only; safe in a browser. Both the UI owner and the backend owner review every change here.

`schema/v1.json` is the whole contract as JSON Schema, generated by `pnpm contracts:schema` and
committed so changes show up in review. CI fails if it is stale or if a change breaks clients built
against the base branch (see [CONTRIBUTING.md](../../CONTRIBUTING.md)).

## Routes

All JSON. A non-2xx response is always `ApiError`. Every response carries `x-outrn-contract: 1.0.0`.

| Route | Request | Response |
| --- | --- | --- |
| `GET /v1/areas` | — | `AreasResponse`: areas, the filter options a request may use (with labels), limits |
| `POST /v1/recommendations` | `RecommendationRequest` (new search) or `{ cursor }` (another page) | `RecommendationResponse` |
| `GET /v1/places/:id` | — | `PlaceDetails` |
| `POST /ops/v1/evaluate` | `RecommendationRequest` | `OpsRunDetail` (every candidate, scores, exclusions) |
| `GET /ops/v1/runs?limit=` | — | `OpsRunList` |
| `GET /ops/v1/runs/:id` | — | `OpsRunDetail` |

Ops routes need `Authorization: Bearer <OUTRN_OPS_TOKEN>` and are not for consumer screens.

## Semantics

- **Status.** `ready`: everything that matters checks out. `check_first`: worth going; something in
  `caveats` needs checking. Decided by the backend; never recomputed in the UI.
- **Evidence.** `published` (a source states it), `reported` (a visitor saw it), `estimate`
  (inferred). An estimate is never shown as a fact. `Provenance.verifiedAt` is a real check;
  `retrievedAt` is only a fetch and is never presented as verification.
- **Unknown is explicit.** `price: { kind: "unknown" }`, `hoursNow.state: "unknown"`, nullable fields.
- **Money** is integer cents plus an ISO 4217 currency. **Times** are ISO 8601 instants; format them
  in the area's IANA `timezone`.
- **Paging.** A search freezes its whole ordered list (`requestId`); pages are slices, fetched with
  `{ cursor }` from `page.nextCursor` / `page.prevCursor`. Lists expire at `expiresAt` (20 minutes:
  the plans assume leaving around `asOf`); then `CURSOR_EXPIRED` returns `restart`, the same search
  to run again.
- **Fewer than three is an answer.** `insufficient` (first page only) says how many qualified and
  offers `relaxations`; the backend never pads.
- **Attribution.** `attributions` lists credits the data sources require wherever their data shows.

### Open-ended codes (current values; more may appear)

| Field | Values today |
| --- | --- |
| `reasons[].code` | `EVENT_STARTS_SOON`, `SHORT_TRAVEL`, `WAIT_FOR_OPENING`, `ENOUGH_TIME`, `CLOSES_SOON`, `OPEN_LATE`, `HOURS_CONFIRMED`, `FREE`, `FITS_BUDGET`, `SUNSET_WINDOW`, `WEATHER_SUITABLE`, `FRESH_REPORT`, `LANDMARK` |
| `caveats[].code` | `HOURS_UNKNOWN`, `HOURS_UNVERIFIED`, `HOURS_APPROXIMATE`, `ADMISSION_UNCONFIRMED`, `ADMISSION_UNKNOWN`, `TOUR_ONLY`, `PRICE_UNKNOWN`, `LATE_ENTRY_UNCERTAIN`, `ACCESS_LIMITED`, `AGE_LIMIT_LIKELY` (params `minAge`), `AGE_LIMIT_UNCERTAIN` (params `minAge`) |
| `insufficient.relaxations[].code` | `longer_travel`, `more_time`, `different_time`, `higher_budget`, `include_paid`, `more_categories`, `stay_later` |
| `category.id` | see `GET /v1/areas` → `filters.categories` |
| `error.code` | `VALIDATION_FAILED` (400, with `fields`), `CURSOR_INVALID` (400), `UNAUTHORIZED` (401), `NOT_FOUND` (404), `CURSOR_EXPIRED` (410, with `restart`), `UNAVAILABLE` (503, retryable), `INTERNAL` (500) |

Every note also carries `text`, the backend's default wording: render it for any code you don't
style yourself.

## Fixtures

`import { areas, scenarios, places, ops, errors } from "@outrn/contracts/fixtures"` — responses
captured from the real API on invented data (`fixtures/osm/*-synthetic.json`). Each scenario is a
search with its pages; the mock API (`pnpm api:mock`) serves them over the real routes. Tests
assert that every fixture matches the schemas and that together they cover every state a screen
must handle. Regenerate with `pnpm fixtures` (needs the local database).
